security-headers-checker

A Python command-line tool that checks a URL for HTTP security headers and explains which are missing, which look misconfigured, and which reveal details about the server.

Problem

Many websites ship without basic HTTP security headers, and nobody notices because the site still works. Checking them by hand means opening the browser's developer tools and knowing what to look for.

Why I built it

I wanted to understand how these headers actually work, not just read about them, and to practise structuring a small Python project properly: a command-line interface, separated modules and tests.†1

What I did

The tool sends one GET request and evaluates the final response in three steps, each in its own module:

  • Fetch (fetcher.py): one request with a timeout, following redirects. Any network error becomes a single FetchError, so the rest of the program doesn't depend on the HTTP library.
  • Evaluate (checker.py): header names are normalised to lowercase, because HTTP treats them as case-insensitive. Each header is checked against a rule defined as data in rules.py.
  • Report (cli.py): a table or JSON, and exit code 1 when a high-severity header is missing, so it can be used in a CI pipeline.

What broke

An early version crashed on a malformed max-age value. I used str.isdigit() to validate it, but that accepts characters like ² that int() rejects, so one odd header from a server brought the whole tool down.

I replaced the check with a try/except ValueError around int() and added a regression test with that exact value.†2

Reviewing the output also showed two limitations I haven't fixed yet: a site that blocks framing with frame-ancestors in its CSP is still reported as missing X-Frame-Options, and a duplicated HSTS header gets the right status but a misleading message.

What I learned

  • Server input can't be trusted, even in a tool meant to inspect servers.
  • A header being present doesn't mean it's configured correctly.
  • Every network request needs a timeout, or the tool can hang forever.
  • Wrapping library errors in my own exception keeps the modules independent.

What I'd improve

  • Accept frame-ancestors as an alternative to X-Frame-Options.
  • Detect duplicated headers and report them clearly.
  • Check cookie flags (Secure, HttpOnly, SameSite).
  • Basic CSP weakness detection, such as unsafe-inline.
  • Run the tests automatically with GitHub Actions.
